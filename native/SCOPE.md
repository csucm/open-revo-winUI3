# 原生核心重写范围

> 本文件保留模块范围与早期阶段记录。当前要求以项目根目录 [PROJECT_SPEC.md](../../PROJECT_SPEC.md) 为准，进度与验收以 [PROJECT_STATUS.md](../../PROJECT_STATUS.md) 为准；新对话先读 [HANDOFF.md](../../HANDOFF.md)。下文的 0.1–0.4 状态和初始命令清单不是当前完成情况。

更新：2026-10-29。依据用户确认：核心功能必须重写；扩展内容保留兼容的可能性，最后实施；插件市场暂不实现。

## 目标

以 WinUI 3 原生控件和 C# 核心服务重写常用控制中心功能。上游源码作为协议、机型差异和行为参考，不启动上游整套后台初始化，不把 Rust 核心的自动恢复和轮询写入直接接进新版。主界面、迷你窗口、OSD 和常规设置不依赖 WebView2。

功能等价以实际可执行操作和结果为准。界面占位、方法声明、模拟测试、读到寄存器、真机操作成功分别记录，不混为完成。

## 核心功能分组

| 分组 | 覆盖范围 | 验收要求 |
|---|---|---|
| 状态与机型 | CPU/GPU、内存、电池、温度、风扇、BIOS/EC 能力识别 | 未知数据不补默认值；不支持的机型停止相应硬件访问 |
| 电源与电池 | Windows 方案、性能档位、充电模式与上限、AC/DC 策略 | 区分系统方案与 EC 档位；确认后操作；返回值及回读验证 |
| 风扇与调校 | 强冷、风扇曲线、CPU/GPU 功耗与频率、配置预设 | 校验参数和供电条件；失败停止；不承诺所有硬件操作均可回滚 |
| 显示与显卡 | 亮度、刷新率、显示器选择、Mini LED、色彩、MUX | 按硬件能力开放；明确重启要求；保留恢复路径 |
| 灯光 | 键盘、分区、灯条、Logo、睡眠行为 | 拓扑及协议匹配；限制帧率；退出释放设备 |
| 设备与系统 | 热键、设备开关、托盘、OSD、自启动、睡眠行为 | 显式开启后台行为；不自动更改系统安全设置 |
| 水冷 | 连接、状态、泵/风扇策略、灯效 | 无设备时仅测试协议与状态机，不标记真机验证通过 |
| 配置与诊断 | 本地设置、预设导入导出、日志、诊断 | 独立数据目录；限制导入大小与字段；不执行导入内容 |
| 原生扩展 | 原生插件、主题、逐项授权的硬件能力 | 网页插件兼容已退出范围，见 REQ-NATIVE-LEAN-01 |
| 插件市场 | 搜索、远程安装、市场管理 | 本轮排除 |

## 源码覆盖清单

初始命令清单的上游提交：`b7d2b526e60cd04965eadab21e606bdb1e1aa56e`。当前集成的 Core 0.9.4 副本固定为 `4ab36ff791a537de79cb8128a93f7dab247c3ee8`；不要混淆两份来源。

`command-inventory.json` / `.csv` 从 `src-tauri/src/lib.rs` 的 `generate_handler!` 提取 198 个命令，并匹配到带 `#[tauri::command]` 的实际定义位置。198 是命令数量，不是用户功能数量；自动后台行为、事件和插件协议还需另行核对。清单中的原生状态是 0.1 预览版的起点，不是完成比例。

## 已发现的行为差异

- 上游电池限制路径不仅修改充电上下限，还可能改写平台身份、平台覆盖寄存器和风扇/模式指示位。不能把该路径视作普通百分比设置直接移植。参考 `crates/openrevo-core/src/driver/ec_bridge.rs::apply_battery_limit_with_override`。
- 上游性能档位会联动 EC、风扇表、CPU/GPU 功耗及部分频率设置；只写模式编号不等于实现完整档位行为。参考 `system/power/ec_mode.rs::apply_ec_hardware_mode`。
- 上游强冷写入部分路径不传播失败；新版必须将写入结果与读取状态分开判断。参考 `driver/wmi_ec.rs::set_fan_boost_hardware`。
- 上游包含原始 EC 写入和邮箱接口。新版 UI/网页扩展不暴露任意地址或任意 IOCTL；通过有明确参数与能力限制的操作接口实现需要的功能。
